# COS-177 · Workspace API ref-readonly — план (Strategy)

> **Статус:** READY к исполнению отдельным code-capable заходом · 2026-09-25 · Strategy.
> **Карточка:** COS-177 · Luna · P1 · `docs/BACKLOG.md` (выдан 2026-09-25).
> **Канон:** FR-004 §2/§7 — Hub→IDE deep-link: `commit` — authority (immutable snapshot).
> **План — поведение и результат; реализация (код/тесты) — отдельным заходом.**

## 1. Зачем

Deep-link из Хаба несёт `commit={sha}` и открывает файл на ревизии finding'а. Сегодня чтение
workspace (дерево/файл) CAS-привязано к голове ветки: клиент фиксирует `head_sha`, сверка с
веткой обязательна, расхождение → 409. После движения ветки старый коммит прочитать нельзя —
ссылка ломается или ведёт не туда. Нужен read-only ref-режим: чтение по произвольному commit
без CAS-привязки к голове.

## 2. Целевое поведение (DoD)

Новый параметр чтения `ref` — commit SHA (полный или ≥7-hex префикс):

1. **Ref-режим (ref задан):** дерево/файл читаются на коммите `ref`; сверка с головой ветки не
   выполняется (ref — authority). `branch`/`head_sha` в этом режиме не требуются и игнорируются.
2. **Приоритет:** `ref` + `head_sha` одновременно → побеждает `ref`; ни 500, ни ложный 409.
   (Устаревший/чужой `head_sha` рядом с валидным `ref` не влияет ни на что.)
3. **CAS-режим (ref пуст):** без изменений — пара branch+head_sha обязательна, сверка головы,
   расхождение → 409. Старые клиенты не замечают изменений.
4. **Деградации:** битый формат `ref` → 400 (деталь называет именно `ref`); несуществующий /
   нерезолвимый `ref` → 404; никаких 5xx.
5. **Read-only by construction:** контракты записи (черновик, коммиты, файловые операции)
   `ref` не получают — write-путь остаётся CAS-only; ref не открывает мутаций.
6. **Ответ файла в ref-режиме:** `sha` и `baseBlobSha` — blob SHA этого коммита (не головы).
   Дерево — прежняя плоская рекурсивная форма, но на коммите.
7. **Контракт:** OpenAPI-артефакты регенерированы из живого приложения; json == yaml == live;
   `ref` виден в OpenAPI обоих чтений.

## 3. Механика: что уже есть (не изобретать)

- Контур compare/gate-scan уже ходит по произвольному ref: **резолв ref → commit SHA** и
  **чтение дерева по SHA**. Ref-режим собирается на этих же примитивах; новых сетевых механик
  не требуется.
- Резолв отдаёт честный `LookupError` на неизвестный ref, а ошибки forge-контура
  нормализуются в HTTP: missing → 404, битый вход → 400, недоступность → 502. Значит контракт
  деградаций (400/404, не 5xx) получается без «своих» кодов поверх.
- Чтение файла уже принимает ref и возвращает blob SHA — в ref-режиме он и становится
  `sha`/`baseBlobSha` ответа. Голова ветки в ответе не участвует.
- Валидация формы — существующий SHA-guard (7–64 hex, регистр любой). Нужен отдельный валидатор
  `ref`: сейчас сообщение 400 говорит `head_sha`, а честный вход — `ref`.
- Ownership-гард (анти-энумерация: чужой repo → 404) уже стоит на обоих чтениях и сохраняется
  в ref-режиме без изменений.

## 4. Тест-план

Юнит (fake forge adapter по конвенции workspace-тестов):

| # | Вход | Ожидание |
|---|---|---|
| 1 | ref = полный старый commit (ветка уже уехала) | 200, snapshot дерева/файла старого коммита |
| 2 | ref = ≥7-hex префикс | 200 (префикс резолвится) |
| 3 | ref несуществующий | 404, не 5xx |
| 4 | ref битый (`zzz`, <7 hex) | 400 |
| 5 | ref + устаревший/чужой head_sha | 200 (ref wins), нет 409 |
| 6 | без ref: branch+head_sha mismatch | 409 (CAS-регресс не сломан) |
| 7 | без ref и без пары branch+head_sha | 400 |
| 8 | файл на ref | `sha`/`baseBlobSha` = blob коммита, не головы |
| 9 | write-DTO | `ref` отсутствует (read-only by construction) |

Контракт: `ref` есть в OpenAPI обоих чтений (docs json + yaml), json == yaml, live-схема
приложения содержит тот же параметр.

Live-smoke (opt-in, живой стенд Gitea + ПУ), сценарий «ветка уехала» — два коммита A→B, ветка на B:

- дерево по `ref=A` → 200 (дерево A); по `branch=main&head_sha=A` → 409;
- файл по `ref=A` → 200 (контент A, blob sha A, не head);
- префикс A → 200; несуществующий ref → 404.

## 5. Верификация (приёмка)

- focused workspace + контрактный гвард: 0 failed.
- Полный suite gate: 0 failed (CAS-путь без регрессий).
- OpenAPI-артефакты регенерированы из живого приложения. *Проверено до изменений: регенерация
  воспроизводит закоммиченные артефакты байт-в-байт — значит дифф после фичи будет ровно дельтой
  параметров (branch/head_sha становятся optional + новый ref), без форматного шума.*
- Live-smoke сценарий выше — зелёный на живом стенде (API :8100, Gitea :3100 — стек поднят,
  тест-PG :5433 доступен).
- Гигиена: `ref` не протёк в write-контракты (DTO-инвариант).

## 6. Границы

## 7. Результат исполнения (Luna, 2026-09-25)

Исполнено в тот же день после planning-захода. Поверхности: чтения workspace API (tree/file),
forge-резолвер, валидаторы форм, новый тест-файл, OpenAPI-артефакты.

- **ref-режим:** `ref` — query, optional, commit SHA (полный или ≥7-hex префикс); при `ref`
  CAS-сверка не выполняется, `branch`/`head_sha` игнорируются; `ref`+`head_sha` → ref wins;
  без `ref` — прежний CAS-путь (пара branch+head_sha обязательна, mismatch → 409). Оба
  CAS-параметра стали optional — это контрактная дельта ref-режима.
- **Деградации:** несуществующий ref → 404, битый → 400, не 5xx. Gitea-квирк 1.22.6
  (`/commits?sha=<unknown>` → 500 "object does not exist") нормализован в `LookupError`
  внутри `resolve_ref`; настоящие 500 не глотаются (отличаются по телу).
- **Файл на ref:** `sha`/`baseBlobSha` — blob SHA коммита (не головы ветки).
- **Read-only by construction:** write-DTO `ref` не принимают (тест-инвариант).
- **Тесты:** `tests/cosmo/test_workspace_ref_readonly.py` — 20 unit/contract passed + 7 live
  passed (opt-in); регресс-сет workspace/openapi/forge/transfer — 637 passed / 0 failed;
  suite gate — **3546 passed / 23 skipped / 0 failed** (471s).
- **Live-smoke:** живой стенд (Gitea :3100 + ПУ :8100), два реальных коммита A→B: tree/file
  по `ref=A` → 200 (snapshot v1), по `head_sha=A` → 409, по `head_sha=B` → 200; префикс A →
  200; несуществующий ref → 404; `ref`+stale `head_sha` → 200. Логин фикстуры — боевой
  (`POST /api/v1/auth/login`): dev-минтинг стенд не принимает после COS-157/175.
- **OpenAPI:** `docs/cosmo-openapi.{json,yaml}` регенерированы из `app.openapi()`;
  json == yaml == live (гвард `test_docs_equal_live_app_schema`); дифф = дельта параметров
  tree/file; регенерация байт-воспроизводима.
- **Не закрыто этой карточкой (не блокер):** FE Web IDE всё ещё ходит в tree/file без
  CAS-пары и без `ref` (finding COS-176) — контракт теперь позволяет ref-only, FE-связка =
  отдельный follow-up. **Блокеры:** нет. Коммит/пуш — по команде Максима.
