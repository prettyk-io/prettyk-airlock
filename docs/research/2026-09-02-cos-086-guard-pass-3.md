# COS-086 — Guard Pass 3: bricks CRUD, plans writes, ProjectTeam anchor

> Статус: **закрыт** · Полный сет: **2298 passed / 2 skipped / 0 failed**

## 1. Что было

COS-083 закрыл capability-гварды для apps/builds/deployments/projects/evidence/
gates/releases/runs и унифицировал резолв домена (`resolve_caller_domain`).
Скан, сделанный при COS-086, показал оставшуюся незакрытой семью **anonymous
writes** и read-поверхности без доменного якоря:

| Поверхность | Дыра до COS-086 |
|---|---|
| `POST/PUT/DELETE /api/v1/bricks[/{id}]` | Без require_principal/capability — anonymous CRUD каталога bricks |
| `POST/DELETE /api/v1/plans[/{id}]` | Аналогично (compile_plan уже был guarded с COS-083) |
| `GET /api/v1/plans`, `GET /api/v1/plans/{id}` | Читали **все** планы всем аутентифицированным, включая чужие домены |
| `GET /api/v1/projects/{id}/team` | Без резолв-контракта — любой аутентифицированный видел team чужого проекта |

Вне карточки (зафиксировано сканом, не трогалось):
`notifications.py` (13 in-body `get_current_principal`, ticket — зона Flash),
`releases.py`/`runs.py` (частичные in-body проверки при наличии гвардов),
`preferences.py` (session-based, COS-012).

## 2. Решение

### 2.1 Выбор capability

- bricks → **`brick:manage`** (`BRICK_MANAGE`): как repo-binding/lc-config —
  каталог bricks меняет семантику компиляции планов во всех доменах.
- plans create/delete → **`pipeline:configure`** (`PIPELINE_CONFIGURE`):
  зеркально `compile_plan`, который уже требовал его с COS-083.

### 2.2 Якорение

- **Brick — глобальный каталог** (`PipelineBrick` без `domain_id`; миграции
  заморожены) → capability-only, доменный ghost невозможен и не нужен.
- **Plan** якорится через `plan.app_id → Application.domain_id` — тот же
  паттерн, что gates в COS-083: `verify_ownership(app, "pipeline", app_id)`.
- **ProjectTeam**: `ProjectTeam` хранит только `project_id` (без собственного
  domain_id) → якорь поведенческий: видимость команды выводится через
  приложения проекта (`_caller_domain_app_ids` intersection). Пустой team —
  валидный 200; проект без видимых приложений → ghost-404.

### 2.3 Правки в `pipelines.py`

| Роут | Гвард |
|---|---|
| `GET /bricks`, `GET /bricks/{id}` | `require_principal` |
| `POST/PUT/DELETE /bricks[/{id}]` | `require_capability(BRICK_MANAGE, identity)` |
| `GET /plans` | `require_principal` + Header + non-admin scoping (батч-мапа app→domain) |
| `POST /plans` | `require_capability(PIPELINE_CONFIGURE, identity)` + Header + ghost по `app.domain_id` |
| `GET /plans/{id}` | `require_principal` + Header + non-admin ghost |
| `DELETE /plans/{id}` | `require_capability(PIPELINE_CONFIGURE, identity)` + Header + non-admin ghost |

`projects.py`: `get_project_team` + Header + non-admin ghost.

Контракт сохранён: `401` anon → `403` нет-capability → `404` ghost. Заголовок
`X-Cosmo-Domain` для admin, identity-биндинг для не-админа — без исключений.
