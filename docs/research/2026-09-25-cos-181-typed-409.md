## Что сделано

Атомарный multi-file коммит (`POST /api/v1/repos/workspace/commits`, COS-124) получил явную
optimistic concurrency и typed-конфликт вместо plain-string шаблонов — серверная половина
merge-loop IDE (IDE-CORE-005/019).

### DTO (`domain/workspace.py`)

- `WorkspaceCommitRequest.expected_head_sha` (alias `expectedHeadSha`, optional) — валидатор
  `validate_head_sha` (полный sha или ≥7-hex префикс; `""`/None → None).

### Route (`api/routes/workspace.py`)

- **Precondition (COS-181 шаг 3b):** `expected_head_sha` разошёлся с головой ветки →
  typed 409 **до любых чтений/записей файлов** (префиксная сверка, как CAS `_check_head`).
- **Три plain-string шаблона заменены** typed-409 (`_workspace_conflict`):
  - create-exists → `kind=exists`, `paths=[path]`, `actual_sha=<существующий blob sha>`;
  - update/delete-missing → `kind=missing`, `paths=[path]`;
  - forge-конфликт (`GiteaConflictError`) → `kind=concurrent` со **свежим** `actual_sha`
    (best-effort re-fetch головы; недоступность forge не маскирует конфликт).
- Без `expected_head_sha` — прежнее поведение: precondition не применяется, per-file CAS
  работает как раньше (форма 409 меняется на typed, это цель карточки).

## Форма typed 409 (контракт для досинка IDE)

Тело — единый error-контракт COS-058 (`transfer_error_handler` разворачивает dict-detail):

```json
{
  "error": {
    "code": "WORKSPACE_CONFLICT",
    "message": "branch head moved in <repo>@<branch>: expected <exp>, actual <act> (refresh workspace and retry)",
    "details": {
      "kind": "concurrent | exists | missing",
      "expected_sha": "<sha | null>",
      "actual_sha": "<sha | null>",
      "paths": ["<conflicting path>"]
    }
  }
}
```

- `kind` совпадает со словарём клиентского `WorkspaceConflictKind` (`exists|missing|concurrent`):
  `concurrent` — branch-level (head/forge), `exists`/`missing` — файловые.
- `paths` — conflicting paths (для branch-level пусто); `details` всегда присутствует.

## Границы (честно)

- Per-file `base_blob_sha` в запросе COS-124 нет → в файловых конфликтах `expected_sha = null`
  (клиентский base sha — отдельный шаг; IDE-CORE-005 упоминает `base_blob_sha`).
- Legacy `POST /workspace/commit` (COS-107) не тронут — вне scope.
- Текущий IDE-клиент (`parseCommitConflict` — string-matching) на новую форму даёт fallback
  `kind=concurrent` (refresh+retry работает); досинк на structured 409 запланирован
  (примечание IDE-CORE-019: «когда Cosmo отдаст typed detail»).
