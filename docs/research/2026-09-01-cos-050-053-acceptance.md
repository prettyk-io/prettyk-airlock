## Accepted behavior

- One release can contain independent TransferItems for multiple artifact
  planes.
- Metadata-only and skeleton/context packages cannot masquerade as deployable
  releases.
- All transport profiles share package identity, SHA-256 manifest checksum,
  idempotency and landing validation semantics.
- Target progression is ordered: received → verified → landing approved →
  imported → bootstrapped → reconciled.
- Bootstrap is impossible before verification and landing approval.
- Checksum mismatch requires a new revision; bootstrap/capacity/reconcile
  failures are recoverable without changing the immutable revision.
- Transport failure and bootstrap failure are classified separately.
- Failure of one TransferItem does not erase sibling items in a multi-plane plan.
- SOD is only an adapter seam; SOD-specific statuses and Kafka mechanics do not
  enter the PureK core contract.

## Follow-up, not blocker
